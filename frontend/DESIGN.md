# frontend

상담원 SPA. 컴포넌트 간 계약은 [ARCHITECTURE.md](../ARCHITECTURE.md). 공간 배치·토큰·ARIA 불변은 [docs/UI_UX_레이아웃_설계안.md](../docs/UI_UX_레이아웃_설계안.md). P5.5부터 Rail + 3-Pane(큐/스레드/컨텍스트) 4-Zone. Living Profile 내용은 P7.

## 내부 설계

- PG에 붙지 않는다. `POST /auth/sign_in`으로 세션 쿠키를 받고 `access_token`을 메모리에 둔다. WS·Application API는 그 Bearer만 쓴다. 쿠키는 JS가 읽지 않는다. 부트스트랩은 `POST /auth/refresh`로 쿠키가 있으면 토큰을 복구한다. HTTP 401은 single-flight refresh 후 같은 요청을 재시도하고, 새 토큰은 `session`과 WS에 같이 넣는다. WS가 닫히면 refresh로 재연결한다.
- TypeScript는 점진 전환이다. `frontend/` 소스·테스트·Vite 설정은 `.ts/.tsx`다. `tsconfig.json`은 `allowJs`를 끄고 앱 소스와 `vite.config.ts`를 검사한다. 테스트는 vitest가 실행한다. `contracts/` 코드젠은 출시 후 WS `message` 경계(`message_created` envelope)에만 붙인다. REST·UI 상태·위젯 `postMessage`는 스키마에 합치지 않는다. shadcn 새 컴포넌트는 `tsx: true`. `cn`은 `src/lib/utils.ts`.
- UI는 Tailwind CSS v4 시맨틱 토큰 + `src/components/ui` shadcn new-york primitives (`Button`/`Input`/`Textarea`/`Label`/`Badge`/`Card`는 `.tsx`, `cn`은 `clsx`+`tailwind-merge`). 레거시 `#ddd` 보더·`font-family: sans-serif`를 두지 않는다. 전역 스토어(Zustand/Redux)는 두지 않는다. 큐는 `store.ts` reduce. `message.created` upsert는 기존 대화의 `status`/`version`/`assigneeId`/`snoozedUntil`/`labels`/`slaBreached`를 유지한다. `typing`은 선택 스레드의 상대 인디케이터만 바꾸고 debounce ~400ms로 WS에 보낸다. `presence`는 레일 `availabilityStatus`만 바꾸고 WS·목록 fetch를 다시 열지 않는다. WS는 `token`·`gatewayUrl`이 바뀔 때만 다시 연다. 가용 점은 `|| "online"` 폴백을 쓰지 않는다.
- 셸은 `100vw × 100dvh`를 Rail(56px) · Queue(320px, `nav[aria-label="대기열"]`) · Thread(`flex-1`, min 480px, 헤더 52px + `ol[role="log"]` + 통합 컴포저) · Context(300px)로 나눈다. `>=1280px` 4영역, `1024–1279px` 컨텍스트는 `dialog[aria-label="고객 정보"]` 드로어, `<1024px`는 큐↔스레드(`대기열로`). 레일은 이니셜 아바타+가용 도트·인박스 unread·`?` 단축키·로그아웃(`DELETE /auth/sign_out`). 큐 카드는 채널(Web/Kakao/Email)·`#displayId`·고객명·상대시각·SLA 보더 / lastContent / 라벨·unread. 헤더는 `#displayId`·고객명·채널·상태 시맨틱 배지(open emerald / pending amber / snoozed slate). 헤더 담당자/스누즈/매크로는 `details[name="thread-actions"]`로 하나만 열고 `Escape`로 닫는다. 타임라인은 고객 `bg-slate-100` 좌측 버블·상담원 우측 버블·내부 메모 앰버이고 새 메시지는 맨 아래로 스크롤한다. 첨부는 클립 아이콘(`첨부 파일`)과 `열기` 카드이고 이미지는 썸네일. 내부 메모 캡션은 `상담원에게만 보임`. 컨텍스트는 고객 프로필·라벨·채널/`#REQ-`·카카오 30일·SLA 잔여. 설정은 좌측 그룹 내비(`nav[aria-label="설정 메뉴"]`, 인박스·콘텐츠·연동·분석) + 본문이고 항목 순서는 인박스 멤버/HMAC/저장응답/라벨/매크로/도움말/웹훅/MCP/Agent Skills/리포트다. 콘텐츠 그룹은 카탈로그 한 화면이 아니라 저장응답·라벨·매크로·도움말을 각각 연다. 인박스는 `session.inboxIds` Select(`aria-label="인박스"`)로 고른다. 상담원 추가는 다른 인박스 멤버 합집합 Select(`aria-label="상담원"`) + `상담원 ID` 폴백이다. Select가 있으면 UUID 인풋(`인박스 ID`/`상담원 ID`/`담당자 ID`)은 `field-fallback`으로 숨기고 ARIA 이름은 유지한다. 로그인·큐 카드·배정·메모·스누즈·라벨·첨부·저장응답·매크로·해결은 이 primitives만 쓰고, [App.test.tsx](src/App.test.tsx) accessible name은 유지한다.
- 부트스트랩 후 `GET .../conversations`로 큐를 채우고, 선택 시 `GET .../messages`로 스레드를 채운다. 목록 JSON의 `contact_name`·`last_activity_at`·`applied_slas`가 큐·컨텍스트를 채운다. 목록 GET 기본은 `resolved`를 제외한다. 담당자 쿼리는 두지 않는다. 큐는 `helpdesk.realtime`의 `message.created`로 upsert한다. 같은 `messages.id`는 무시하고, 같은 내용의 `pending-*` 낙관적 버블은 서버 id로 교체한다. 선택하지 않은 대화는 unread를 올린다. `resolved`는 큐에서 숨긴다. `pending`은 큐에 남긴다. `sla_breached`면 큐 카드에 SLA 뱃지를 단다. 큐 카드는 채널·티켓번호·시각 / lastContent / 라벨·unread 3행이다.
- 답장은 `POST /api/v1/accounts/{account_id}/conversations/{id}/messages`에 `inbox_id`·`contact_id`·`contact_inbox_id`를 넣는다(게이트웨이가 대화 행을 조회하지 않음). 전송은 낙관적이다: 로컬 `pending-*` 버블을 `status: "sending"`(투명도 70%)로 즉시 붙이고 실패하면 `재전송`을 보여 준다. 서버 `message_id` 또는 같은 내용의 `message.created`가 오면 pending을 교체한다. 배정은 인박스 멤버 Select(+ 나에게 배정)로 고르는 즉시 `PUT .../assignee`. 내부 메모는 `POST .../notes`이고 답장과 같이 낙관적 버블(`재전송`)을 쓰되 큐 lastContent를 바꾸지 않는다. 스누즈는 프리셋(1시간 뒤·오늘 오후 6시·내일 09:00·다음 주 월요일)을 누르면 바로 `PUT .../snooze`하고, `datetime-local` 폴백은 RFC3339로 바꿔 같은 API를 쓴다. HMAC은 보기 전에 `••••••••`로 가리고 복사하면 `복사됨`을 보여 준다. 같은 패널에서 administrator가 `greeting_message`와 영업시간 JSON을 `PATCH .../inboxes/{id}`로 저장한다. 비이미지 첨부는 📄 아이콘이다. `status=snoozed`이면서 `snoozedUntil`이 아직 미래면 큐에서 숨긴다. 라벨은 컨텍스트 패널에서 카탈로그 칩을 누르거나 datalist로 이름을 고르고 `POST .../conversations/{id}/labels`로 부착, `DELETE .../labels/{label_id}`로 조인만 뗀다. 카탈로그 라벨·저장응답·공유 매크로(`매크로 저장`)와 인박스 멤버·HMAC은 administrator 설정 뷰에서 만들고 고치고 지운다. `나에게 배정`은 바로 `PUT .../assignee`한다. 첨부 크기는 1024B 이상이면 KB다. 통합 컴포저는 답장/메모 탭 + 클립·드롭·붙여넣기 즉시 첨부(`첨부` 버튼은 폴백). 메모 폼(`form.note`)은 답장과 같은 textarea+전송 한 줄이고, 도크·필드·`메모` 버튼만 앰버다 + `/short_code` 팝오버(`ul[role="listbox"][aria-label="저장응답"]`, 화살표·Enter로 고르고 Escape로 `/` 토큰을 지운다). 인박스·담당자 native `select`는 시맨틱 보더 토큰을 쓴다. 답장 placeholder는 `/ 를 입력해 저장응답 삽입`이다. 매크로 실행은 스레드 헤더에서 `POST .../macros/{id}/execute`하고, `⌘K`는 메뉴를 연 뒤 첫 `실행`에 포커스한다. administrator의 생성 폼은 헤더에 두지 않는다. 첨부는 `POST .../attachments` multipart `file`이다. 해결 영역은 `PUT .../status`로 `pending` 또는 `resolved`다. `pending`은 큐에 남고 `resolved`만 숨긴다.
- 로컬 개발은 Vite가 `/auth`·`/api`·`/ws`를 클러스터 프론트 NodePort `http://127.0.0.1:30080`으로 프록시한다. nginx가 그 origin의 `/api`·`/auth`·`/ws`를 `gateway-web`으로 넘긴다. compose에서 `go run ./cmd/gateway-web`만 쓸 때는 프록시 대상을 `:8080`으로 되돌린다. 브라우저 CORS를 게이트웨이에 열지 않는다. 프로덕션 이미지(`nginx.conf`)는 같은 경로를 `gateway-web.aura.svc.cluster.local:8080`으로 프록시한다. `index.html`은 `Cache-Control: no-cache`로 재검증하고, 해시된 `/assets/`만 immutable이다. 빈 `gatewayUrl`이면 브라우저가 상대 경로로 프론트 origin을 치고, nginx가 게이트웨이로 넘긴다. 위젯 소스는 이미지에 넣지 않고 고객사에 압축 아카이브로 배포한다.
- 부트스트랩: 로그인 화면. 레일에서 대기열과 설정(administrator만)을 가른다. Agent는 시크릿을 보지 않는다. 설정은 좌측 그룹 내비. 인박스 멤버는 추가·목록·행 삭제. 저장응답·라벨·매크로는 콘텐츠 그룹에서 따로 열고, 목록에서 고르면 아래 폼에 채워 수정하고 행마다 삭제. 웹훅은 URL 등록·수정·삭제(`message_created` 구독). 도움말은 목록에서 고르면 폼에 채워 수정, 행 삭제. MCP·Agent Skills는 목록에서 고르면 upsert, 행마다 삭제. 설정 저장 버튼(`라벨 추가`·`문서 게시`·`웹훅 추가`·`MCP 추가`·`스킬 저장` 등)은 `div.settings-form-actions`에서 `size="sm"`이고 오른쪽 정렬이다. MCP `auth_header`는 HMAC처럼 보기 전 `••••••••`, 재발급은 고른 서버(없으면 첫 행). 리포트는 GET /reports 현재 수치만 차트로 그린다. CSAT%·SLA는 막대, 대화 상태는 도넛, 상담원·인박스는 가로 막대다. Tooltip 호버 커서(회색 박스)는 그리지 않는다. 시계열·CSAT 분포·SLA 세부 비율은 두지 않는다. `?fixture=1`은 WS 없이 큐·스레드를 채운다. 컨텍스트 패널은 라벨·채널·SLA와 Living Profile(`section[aria-label="Living Profile"]`, PainPoint rose / Product blue / Preference emerald / Feature violet). 스레드 `content_type=form`은 도구 승인 카드(`[승인 및 실행]` → `POST .../tools/{execution_id}/approve`). 셸·브레이크포인트는 P5.5 그대로다. Mine/미배정/라벨 폴더·URL 딥링크는 출시 후. 단축키 `J`/`K`/`R`/`N`/`⌘Enter`/`E`/`⌘K`(매크로).

## Commands

저장소 루트 기준.

```sh
cd frontend
npm test
npm run typecheck
npm run dev
```

프록시 대상은 클러스터 SPA NodePort `127.0.0.1:30080`. 실WS는 그 origin의 `/ws`다. compose 게이트웨이만 쓸 때는 `127.0.0.1:8080`.

VS Code Run and Debug `Frontend: Vite`는 `frontend/`에서 `npm run dev`를 띄운다. `/auth`·`/api`·`/ws`는 쿠버네티스 프론트(`:30080`)로 프록시한다.
